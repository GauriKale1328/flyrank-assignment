Refresh Priority Scoring for Content Optimization Using Search Performance Signals

A Search Intelligence capstone using FlyRank search-performance data to identify and rank pages for content-refresh attention.

Abstract

This research asks how search-performance signals can be used to prioritize content pages for potential refresh. A transparent rule-based refresh-priority baseline was combined with a Logistic Regression model using impressions, clicks, CTR, and average search position. The model was evaluated on a held-out 20% test split and achieved 98.46% accuracy, 98.23% precision, 97.03% recall, 97.63% F1-score, and 99.91% ROC-AUC. The resulting priority ranking concentrated observed refresh opportunities into a smaller high-priority group, with a 95.47% capture rate for observed refresh pages in the development sample. The output is framed as a decision-support and prioritization workflow rather than causal evidence of future ranking or refresh impact.

1. Introduction / Problem Statement

Content teams may have many pages that could potentially benefit from review or refresh. A practical challenge is deciding which pages should receive attention first.

This capstone focuses on the decision: Which content pages should be prioritized for refresh based on observable search-performance signals?

The goal is not to claim that a model can prove Google's ranking algorithm or guarantee the outcome of a content refresh. Instead, the goal is to create a repeatable ranking and decision-support workflow that helps focus review efforts on a manageable set of pages.

2. Data

The analysis uses the FlyRank internship warehouse, specifically the fact_content_daily_performance table.

The selected development window is March 2026 (2026-03), covering March 1 through March 31, 2026.

For model development and experimentation, a 100,000-row sample from the March 2026 data was used.

Predictive Signals

  • GSC impressions
  • GSC clicks
  • Click-through rate (CTR)
  • Average search position

Excluded Fields

Label-derived fields such as trend_direction, trend_pct, and is_declining_label were excluded to reduce leakage risk.

Client and content identifiers were not used as predictive features. No client names, domains, private queries, credentials, or raw exports are included in this public paper.

3. Methodology

Baseline

A transparent baseline refresh-priority score was used as the starting decision rule. The binary proxy target for modeling was defined as:

Refresh-priority class = 1 when baseline_score ≥ 3

Model

Logistic Regression was trained using four search-performance features: impressions, clicks, CTR, and average search position.

Validation Design

The development sample was divided into training and test sets using an 80/20 split with a fixed random state and stratification by the proxy target.

The test set was kept separate from model fitting and was used for final evaluation.

Leakage Checks

Features directly derived from the target or future performance information were excluded. The model therefore uses observable search-performance signals rather than the target-derived fields themselves.

4. Results

The Logistic Regression model was evaluated on the held-out 20% test split.

98.46% Accuracy
98.23% Precision
97.03% Recall
97.63% F1 Score
99.91% ROC-AUC

Interpretation

The results show that the selected search-performance features can reproduce the refresh-priority proxy with high agreement.

Because the target is derived from the rule-based baseline_score, these metrics should not be interpreted as proof that the model predicts real-world refresh outcomes.

The model is therefore treated as a probability-based decision-support layer that reproduces the transparent baseline while enabling ranking and prioritization.

5. Ranked Recommendations

The final workflow converts model outputs into practical priority buckets for content review.

Priority Pages Observed Refresh Rate
Low 13,352 0.61%
Medium 342 62.57%
High 6,306 98.83%
High-priority capture rate: 95.47%
6,232 of 6,528 observed refresh pages were captured in the High-priority bucket.

Action Playbook

  • High priority: review first for potential content refresh opportunities.
  • Medium priority: monitor and review when additional content or business context supports action.
  • Low priority: maintain monitoring and avoid unnecessary refresh effort unless other evidence appears.

These recommendations are intended to help allocate review effort; they are not claims that refreshing a page will cause improved rankings, traffic, or clicks.

6. Feature Interpretation

Logistic Regression coefficients indicate the direction of association between each search-performance feature and the refresh-priority proxy.

Positive coefficients indicate a positive association with the predicted refresh-priority class, while negative coefficients indicate a negative association.

Because the features have different measurement scales, raw coefficient magnitudes should not be interpreted as directly comparable feature-importance scores.

7. Limitations & Honest Framing

  • The modeled target is a proxy derived from the baseline score, not a directly observed business outcome.
  • The development analysis uses a 100,000-row sample from the March 2026 data window.
  • The results describe observed relationships in the analyzed sample and should not be interpreted as causal evidence.
  • The model does not prove or explain Google's ranking algorithm.
  • A high-priority recommendation means "review this page first," not "refreshing this page will definitely improve performance."
